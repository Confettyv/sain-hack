# Sain: эксперт как плейлист (кейс 4, команда «Кисы», team01)

Три вымышленных эксперта по сну отвечают на один вопрос пользователя каждый в своём стиле, с опорой
на одну научную статью из базы, и вежливо отказывают в диагнозах, лекарствах и дозах.

## Как устроено

```
реплика ─► разбор пачкой (модель): атака или нет, какая статья, слова для поиска
        ─► раздел статьи кодом (BM25 по английским словам)
        ─► три ответа одним вызовом (модель) с отрывком раздела и карточками экспертов
        ─► фильтр кодом: дозы, диагнозы, обращения к проверяющему ─► повтор или запасной текст
```

- Ссылка у тройки одна и та же: так требует метрика V.
- Эксперты — данные: роль и стиль из набора организаторов + рецепт письма в `experts/<id>.md`.
- Модель не ответила — группа получает запасной текст с той же ссылкой, `/run` не падает.
- `LLM_FAKE=1` или нет ключа — поддельная модель, весь путь работает без токенов.

## Запуск

```
python3 -m venv .venv && ./.venv/bin/pip install ruff mypy   # только для разработки
LLM_FAKE=1 PORT=8000 HACK_TEAM_TOKEN=... ./.venv/bin/python main.py
```

На стенде: `sh start.sh`, зависимостей нет (`requirements.txt` пуст, только stdlib).
Переменные стенда: `PORT`, `HACK_API_URL`, `HACK_TEAM_TOKEN`, `LLM_BASE_URL`, `LLM_API_KEY`, `LLM_MODEL`.
Свои: `LLM_FAKE`, `LLM_REASONING` (low), `TOKEN_CAP` (200000), `ASK_LIMIT` (20 в час), `ASK_BUDGET` (30000).

## API для клиента

Базовый адрес: `https://team01.hack.be-healthy.tech`. CORS открыт.

`GET /experts` → `{"experts":[{"expert_id","name","tagline","role","speech_style"}]}`

`POST /ask` — один вопрос одному эксперту:

```json
{"expert_id": "biohacker", "text": "Пью кофе в 17:00, мешает ли это сну?",
 "history": [{"role": "user", "text": "..."}, {"role": "assistant", "text": "..."}]}
```

Ответ `200`:

```json
{"expert_id": "biohacker", "text": "...", "refused": false,
 "citations": [{"article_id": "art_20", "section_id": "s004", "article_title": "...",
                "section_title": "...", "year": 2021, "doi": "..."}]}
```

Ошибки: `400` нет `text` или неизвестный `expert_id`; `429` лимит вопросов; `502` модель не ответила;
`503` набор не загрузился. Ответ идёт 5–15 с: клиенту нужен индикатор «эксперт пишет».
Чтобы показать «плейлист» (три эксперта на один вопрос), клиент шлёт три `/ask` параллельно.

`GET /stats` — сколько токенов потрачено. `GET /` — живой ли сервер.

`POST /run` — только для стенда проверки, клиент его не вызывает.

## Проверка

```
./.venv/bin/ruff check . && ./.venv/bin/mypy sain main.py tools && ./.venv/bin/python -m unittest -q
LLM_FAKE=1 ./.venv/bin/python tools/score.py d4.json --validate api.token   # формат, без токенов
./.venv/bin/python tools/score.py d4.json --classify-only                   # S/G по эталону, ~10k
./.venv/bin/python tools/score.py d4.json --groups 4 --out a.json           # живые ответы, ~23k
./.venv/bin/python tools/vcheck.py d4.json a.json                           # V судьёй, ~14k
```

`d4.json` — dev-набор с эталоном (`GET /case/4/getData?dataset_code=case4-dev-v2`), в репозиторий
не кладём. Токены и ключи — только в env, не в коде и не в логах.
